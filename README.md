# 청빙 작업대 — Phase 1

담임목사 청빙에 필요한 서류를 **공고와 무관하게 매일 축적**하는 1인용 작업대.
사양은 [`청빙-에이전트-개발지시문.md`](./청빙-에이전트-개발지시문.md) 를 따른다.

Phase 1 범위는 자산 은행 · 서류 작업대 · 코칭 · 증빙 관리 · 준비도 대시보드다.
**공고 수집(크롤링)은 Phase 3 이며 여기에는 없다.**

## 설계상 지켜지는 것

이 도구는 **대필자가 아니라 코치**다. 그 원칙을 문장으로 적어두는 대신 구조로 막았다.

| 원칙 | 어떻게 보장했는가 |
|---|---|
| 서류를 통째로 써주지 않는다 | 그런 함수가 `lib/llm.ts` 에 없다. LLM 사용처는 조각 추출·문장 다듬기 두 곳뿐 |
| 뼈대는 내용 없이 | `lib/outline.ts` 가 섹션 체크리스트에서 **결정적으로** 생성한다 (LLM 미사용) |
| 추출 조각을 자동 저장하지 않는다 | LLM 결과는 `evidence_candidate` 까지만 들어간다. `evidence` 로 쓰는 경로가 없다 |
| 수치·날짜를 추측해 채우지 않는다 | 프롬프트 + `parsePartialDate()` 가 빈 값을 `null` 로 둔다. 승격 시 `verified=false` 강제 |
| 문장 다듬기가 내용을 바꾸지 않는다 | 원문에 없던 숫자가 생기면 결과를 `safe=false` 로 돌려주고 반영을 막는다 |
| 코칭은 지적만 한다 | 질문 문장이 코드에 고정 템플릿으로 박혀 있다. LLM 이 끼어들 자리가 없다 |

## 비용 — 기본값은 0원이다

9개 기능 중 7개는 모델이 필요 없다. 완성도 점검, 코칭 질문, 뼈대 생성, 버전 관리,
연표 공백 탐지, 증빙 관리, 대시보드는 전부 규칙 기반이다.

모델이 관여하는 곳은 둘뿐이고, 둘 다 선택이다.

| 기능 | 기본 | 대안 |
|---|---|---|
| 과거 서류 → 조각 분해 | **규칙 기반 (무료)** | 키가 있으면 Claude 분해 선택 가능 (문서 1장당 약 $0.05) |
| 문장 다듬기 | 비활성 | 키가 있을 때만 동작 |

**규칙 기반 분해**(`lib/extract-rules.ts`)는 날짜 범위·숫자+단위·불릿을 찾아
원문에서 **글자를 잘라 옮기기만** 한다. 그래서 LLM 분해보다 나은 점이 하나 있다 —
사실을 지어내는 것이 구조적으로 불가능하다. 적혀 있지 않은 날짜는 비워 두고,
어차피 후보는 전부 사람이 승인한다.

못 하는 것도 분명하다. 문맥을 읽어 요약하거나 여러 문단에 흩어진 사실을 하나로 묶지
못한다. 그게 필요하면 `ANTHROPIC_API_KEY` 를 넣고 업로드 시 'Claude' 를 고르면 된다.

## 시작하기

```bash
npm install
cp .env.example .env.local      # DATABASE_URL, APP_SECRET 채우기
npm run db:migrate              # 스키마 + 증빙 12종 시드
npm run dev
```

`http://localhost:3000` 에서 `APP_SECRET` 을 입력하면 들어간다.

### Supabase 로 옮길 때

`DATABASE_URL` 을 Supabase 연결 문자열로 바꾸고 `npm run db:migrate` 를 한 번 더 돌리면 된다.
파일 보관까지 옮기려면 `STORAGE_DRIVER=supabase` 와 `SUPABASE_*` 를 채운다.

## "21종" 의 구성

사양서 4장: 내가 쓰는 서류 9종(A) + 발급 증빙 11종(#10~20, B) + 추천서 1종(C) = **21종**.
증빙 테이블에는 B + C 를 합쳐 12행이 들어간다.

**완료 판정**(`lib/readiness.ts` 의 `isDocComplete`):
서류는 완성도 70점 이상 **이고 필수(blocker) 지적이 0건**, 증빙은 보유중이며 유효기간 내.
점수만으로 세면 7년 연표 공백이 있는 이력서가 "완료"로 잡히기 때문에 두 조건을 함께 본다.

## 검증

```bash
npm test            # 단위 테스트 55개
npm run db:smoke    # 완료 기준 전 경로를 실제 DB 로 (업로드→분해→승인→v1→점수→질문)
```

`db:smoke` 에는 **대역(mock)이 없다.** 규칙 기반 분해를 쓰므로 LLM 호출 없이
전 경로가 실제 코드로 돈다.

`ANTHROPIC_API_KEY` 를 넣었다면 LLM 경로도 따로 검증할 수 있다:

```bash
npm run verify:llm  # 함정을 심은 원문으로 실제 호출 → 환각 자동 검출 (약 $0.03)
```

환각 판정 로직은 `lib/llm-audit.ts` 에 있고, **일부러 환각을 심어 넣고 잡히는지**
단위 테스트로 먼저 검증했다 (지어낸 인용, 반올림한 수치, 원문에 없는 연도).
실패를 못 잡는 검사기는 쓸모가 없기 때문이다.

브라우저 검증까지 보려면 dev 서버를 띄운 뒤:

```bash
npm i --no-save playwright
bash scripts/verify.sh
```

`db:smoke` 는 **DB 를 비우고 시작한다**. 실제 데이터가 들어간 뒤에는 돌리지 말 것.
